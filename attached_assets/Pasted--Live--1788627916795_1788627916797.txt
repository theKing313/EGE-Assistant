Сейчас приложение успешно опубликовано и имеет статус Live.

Сделай ТОЛЬКО финальную проверку готовности SmartEGE к запуску.
Ничего не переписывай и не рефактори без необходимости.

Проверь по порядку:

1. FRONTEND
- открывается ли production URL;
- работает ли основная UI;
- нет ли критических ошибок в browser console;
- корректно ли frontend обращается к production backend.

2. BACKEND
- запускается ли production backend;
- правильный ли production PORT;
- слушает ли сервер 0.0.0.0;
- работает ли /api/health или аналогичный health endpoint;
- нет ли критических ошибок при старте.

3. GIGACHAT
- действительно ли backend использует GigaChat;
- корректны ли AI_PROVIDER, GIGACHAT_MODEL и GIGACHAT_SCOPE;
- работает ли получение токена и тестовый AI-запрос;
- используется ли текущий GigaChat AUTH/CLIENT SECRET из Secrets;
- не выводятся ли секреты в логи;
- проверь, какой режим тарификации/доступа фактически настроен по текущему scope;
- если используется pay-as-you-go, НЕ пытайся проверять его через /balance и НЕ меняй тариф;
- проверь фактическое использование токенов/лимитов в коде, если такая логика уже есть;
- проверь, есть ли защита от бесконечных AI-запросов и слишком большого расхода;
- проверь обработку ошибок 401/402/429/5xx.

4. DATABASE
- подключается ли production database;
- существует ли нужная схема/таблицы;
- не используется ли случайно development DATABASE_URL вместо production;
- проверь, что данные пользователей, Premium и платежей смогут сохраняться после публикации.

5. YOOKASSA
- есть ли production Shop ID и Secret Key в deployment secrets;
- есть ли webhook endpoint;
- не активируется ли Premium только по redirect без подтверждения payment.succeeded;
- проверь, что Premium активируется только после успешной проверки платежа;
- не выводятся ли секреты в логах.

6. PREMIUM / ЛИМИТЫ
- проверь текущую логику Free/Premium;
- проверь лимит AI-запросов;
- проверь, что Premium не становится автоматически активным без оплаты;
- проверь, что при временной недоступности GigaChat Premium не ломается;
- проверь обработку ситуации, когда AI временно недоступен.

7. PRODUCTION CONFIG
- проверь production secrets;
- проверь VITE_API_URL;
- проверь, что production frontend обращается именно к production backend, а не к старому Replit dev URL;
- проверь CORS и cookies/session configuration для production domain.

ВАЖНО:
- не меняй архитектуру;
- не удаляй БД;
- не меняй тарифы GigaChat;
- не меняй YooKassa;
- не переписывай рабочие файлы;
- не создавай новые файлы без необходимости;
- не коммить node_modules;
- не делай большой рефакторинг;
- не запускай длинные автономные исправления.

Если всё работает — НИЧЕГО НЕ МЕНЯЙ.

В конце дай только короткий отчёт:

✅ Frontend
✅ Backend
✅ GigaChat

Если найдена проблема — сначала только укажи её и предложи минимальное исправление. Самостоятельно менять код разрешено только для действительно критической production-проблемы.

Главная цель — АУДИТ, а не разработка новой версии проекта.
